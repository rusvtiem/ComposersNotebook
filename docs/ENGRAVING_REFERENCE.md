## 1. Базовая единица — staff space (sp)

- **sp** = расстояние между двумя соседними линиями стана. Это ГЛАВНАЯ единица: размер
  почти всех объектов масштабируется от sp.
- MuseScore по умолчанию: sp = 1.75 мм → высота стана (4 промежутка) = 7 мм.
- Головка ноты ≈ 1 sp по высоте, ≈ 1.2–1.3 sp по ширине.

**У нас:** `staffLineSpacing` играет роль sp (StaffAreaView). Модель верная — от sp считаем
высоты. Это ОК, менять не надо.

---

## 2. Стан (staff)

- 5 линий, 4 промежутка. Ноты сидят на линиях и в промежутках, ledger lines сверху/снизу.
- Ключ (clef) задаёт привязку высот к линиям. Один стан = один инструмент через всю партитуру.
- **Grand staff** (рояль): 2 стана, связаны фигурной скобой (brace). Разрыв между станами
  фиксирован высотной непрерывностью: нижняя линия скрипичного = E4, верхняя басового = A3,
  между ними 2 sp, C4 (middle C) — на добавочной линии по центру.

**У нас:** `grandStaffGap = 2 * staffLineSpacing` с корректным обоснованием E4/A3 (StaffAreaView:44-49).
Модель верная.

## 3. Многоинструментальная партитура — САМОЕ ВАЖНОЕ расхождение (баг 7, частично 2)

**Стандарт (MuseScore, Gould):**
- **Система (system)** — одна строка музыки, содержащая **станы ВСЕХ инструментов**, поставленные
  друг под другом.
- Перенос на новую строку происходит **для всей партитуры целиком**: если система рвётся на
  такте N, она рвётся на такте N у ВСЕХ инструментов.
- Границы одного и того же такта у всех инструментов стоят на **одном X** — такты выровнены
  столбиком по вертикали. Ширина такта определяется по «самому тесному» инструменту в этом такте.
- **Brackets** группируют станы инструментов одной семьи (духовые, струнные); **braces** —
  станы одного инструмента (grand staff). Вертикальные отступы: `staff distance` между
  инструментами, `grand staff distance` внутри инструмента, доп. отступ вокруг скобок.

**У нас (расхождение):** `StaffAreaView.body` (:57) идёт `ForEach` по `score.parts` и для КАЖДОЙ
партии отдельно зовёт `EngravingEngine.computeLayout` (:68) только по её собственным тактам.
→ Каждый инструмент считает свои переносы систем независимо. У флейты система может рваться на
5-м такте, у рояля на 6-м → станы разъезжаются, такты не выровнены. Плюс ширина такта считается
по одному инструменту, а не по максимуму среди всех.

**Что нужно:** считать раскладку ОДИН раз на всю партитуру: для каждого такта взять максимальную
ширину среди всех инструментов, затем разбить на системы едиными границами, затем рисовать все
инструменты по этим общим границам и общим ширинам тактов. Скобка/скоба слева для группировки.

## 4. Горизонтальный spacing нот — ЛОГАРИФМ, а не линия (влияет на 2 и читаемость)

**Стандарт (LilyPond springs-and-rods, Gould, традиция XVIII в.):**
- Spacing **логарифмический** от длительности, НЕ прямо пропорциональный.
- Модель: `space = shortest-duration-space + (кол-во удвоений длительности) * spacing-increment`.
- LilyPond defaults: `spacing-increment ≈ 1.2 sp` (~ширина головки), `shortest-duration-space = 2.0`.
  → кратчайшая нота получает ~2.4 sp.
- Практически: восьмая → +1 ширина головки, четверть → +2, половина → +3, целая → +4.
  (При ЛИНЕЙНОЙ пропорции целая была бы в 8 раз шире восьмой — слишком широко и некрасиво.)
- «Most common shortest duration»: в каждом такте берётся кратчайшая длительность как база
  (не короче восьмой), чтобы редкая шестнадцатая не разносила весь такт.

**У нас (расхождение):** `EngravingEngine.measureContentWidth` (:104) считает ширину ноты
**линейно**: `proportional = actualBeats / totalBeats * 160 * z`. Это прямая пропорция.
Любопытно: `EngravingEngine.proportionalWidths` (:153-177) уже содержит правильную смешанную
формулу `ratio*0.6 + logScaled*0.4`, но она НЕ используется основным путём раскладки.

**Что нужно:** перейти на логарифмическую модель `база + log2(dur/shortest) * increment` в
основном расчёте ширины; свести к одной формуле и убрать неиспользуемый дубль.

## 5. Ввод нот — replace/overwrite mode (баг 3, частично 4)

**Стандарт (MuseScore step-time):**
- Ввод идёт в режиме **«замена/overwrite»**, а не «вставка». Экран разбит на слоты по длительностям.
- Workflow: сперва выбрал длительность → потом высоту. Нота встаёт в текущий слот, **заменяя** то,
  что там было (паузу или ноту). Удалять предварительно не нужно.
- **Выбор паузы и ввод с неё:** пауза выбирается как обычный объект; ввод ноты заменяет паузу.
  Если новая длительность короче паузы → пауза дробится: нота нужной длительности + остаток-пауза.
  Если длиннее → перекрывает следующие слоты.
- Смена длительности выбранной ноты/паузы: в норм-режиме клавиши 1–9 (конкретная длительность);
  в режиме ввода Shift+W/Q (больше/меньше). Пауза-переключатель — клавиша 0.
- Touch-редакторы (StaffPad, Notion, Symphony Pro): режим Select одним касанием для
  правки/транспозиции; рисование пером/пальцем → мгновенный типсеттинг; контекстные меню.

**У нас (расхождение):** `insertEvent` (ScoreViewModel:202) всегда `.append(event)` в конец такта.
`clearPlaceholderRest` (:227) убирает только whole-rest-плейсхолдер, когда он единственный.
→ Нельзя выбрать паузу в середине такта и ввести с неё, нельзя раздробить паузу — только дописать
в конец. Это ровно баг 3.

**Что нужно:** ввод должен работать от позиции курсора/выбранной паузы: заменять выбранную паузу
нотой той же длительности, а при более короткой длительности — дробить паузу на ноту + остаток-паузы.
Модель слотов вместо «append в конец».
