# Ось 1 — Инженерия (архитектура, Swift/SwiftUI, состояние, ошибки)

Проверено на коммите 32df230, 10.07.2026. Статусы: ✅ verified лично / 🔎 reported (не подтверждено) / ❌ false-positive.

## Стандарт, с которым сверяемся

- **Value semantics Swift**: модель на struct + COW — правильный выбор для undo (снимки независимы). Мутации через `mutating func` на владельце. Apple: "Choosing Between Structures and Classes".
- **SwiftUI single source of truth**: `@Published` состояние в одном `ObservableObject`, view — производная. Дорогие вычисления не в `body`.
- **Fail-fast на границах, доверие внутри**: force-unwrap только там, где инвариант доказан; на границах (файлы, парсинг, аудио) — обработка ошибок, не молчаливый `try?`.
- **Инварианты типами**: если «все партии имеют равное число тактов» — это должно быть невозможно нарушить, а не подразумеваться.

## Критичное

### E-1 ✅ Инвариант «равное число тактов у всех партий» не выражен ничем
- **У нас**: `Score.parts` — массив `Part`, каждая со своим `staves[i].measures` (Part.swift:36). Синхронность длины держится только тем, что операции идут через `Part.appendEmptyMeasure/insertMeasure/removeMeasure` (Part.swift:97-113), применяющие ко всем станам. Но никакой проверки/типа, что `parts[a].measureCount == parts[b].measureCount`, нет.
- **Стандарт**: в партитуре такт N существует одновременно у всех инструментов (система — вертикальный срез). MuseScore/Gould: границы такта выровнены столбиком. Число тактов — общий инвариант партитуры, не свойство партии.
- **Расхождение**: если хоть один путь мутирует один стан/партию мимо общих операций — длины разъезжаются. `StaffAreaView` затем берёт `measureWidths[measureIndex]` по индексам — рассинхрон длин → потенциальный out-of-bounds краш и разъезд систем (корень бага 7).
- **Критичность**: high. Чинить архитектурно: единый timeline тактов на уровне Score, партии держат только содержимое ячеек.

### E-2 ✅ `Part.measures` / `Part.clef` — аксессоры только на `staves[0]`, басовый стан невидим
- **У нас**: Part.swift:72-87. `get` → `staves.first`, `set` → `staves[0]`. Комментарий признаёт «backwards compatible». Для grand staff (рояль) `part.measures` возвращает и пишет ТОЛЬКО скрипичный стан; басовый молча игнорируется. `set` при пустом `staves` молча ничего не делает (`guard ... else { return }`, :75).
- **Стандарт**: grand staff — один инструмент, два стана равноправны по содержимому. Доступ «партия → такты» неоднозначен и должен быть явным (`staff(index).measures`), а не «первый стан по умолчанию».
- **Расхождение**: любой legacy-путь через `part.measures` для рояля работает с половиной данных. Молчаливый провал сеттера — классический silent failure.
- **Критичность**: high. Убрать двусмысленные аксессоры, обращаться к станам явно.

## Высокое

### E-3 ✅ Один и тот же горизонтальный spacing считается тремя путями по-разному
- **У нас**: ширина такта — `EngravingEngine.measureContentWidth` по `event.actualBeats` (EngravingEngine.swift:104); X-позиции нот внутри такта — по `event.duration.beats` (StaffAreaView.swift:333 hit-test и :620 render, плюс `cumulativeBeats += event.duration.beats` :732); спаннеры (`xForBeat`) — снова по `actualBeats` (:843). Для триолей `duration.beats ≠ actualBeats` (триольная восьмая: 0.5 vs 0.333).
- **Стандарт**: одна модель spacing на всё — layout, hit-test, рендер и привязка спаннеров обязаны использовать одну систему координат по долям. Иначе нотоглав, зона тапа и хэйрпин указывают на разные X.
- **Расхождение**: в тактах с триолями/смешанной длительностью нотоглавы (`duration.beats`) и спаннеры (`actualBeats`) разъезжаются; зона тапа не совпадает с рисунком.
- **Критичность**: high. Свести к одной величине (`actualBeats`) во всех трёх путях; вынести позиционирование в один сервис.

### E-4 ✅ Ввод ноты — `append` в конец, а не replace/overwrite по курсору
- **У нас**: `insertEvent` (:202-224) прочитан построчно: всегда `.append(event)`, две ветки — «влезает в остаток такта → append» и «не влезает → advanceMeasure → append». Ни одной ветки replace выбранной паузы или её дробления. `clearPlaceholderRest` (:227) снимает только одиночный whole-rest-плейсхолдер. `addNote` при `selectedEventIndex != nil` строит АККОРД (`addPitchToSelectedEvent`, :132-137), а не заменяет.
- **Стандарт**: MuseScore step-time — режим замены: нота встаёт в слот курсора, заменяя паузу; короче паузы → пауза дробится (нота + остаток-пауза). См. `ENGRAVING_REFERENCE.md` §5.
- **Расхождение**: нельзя выбрать паузу в середине такта и ввести с неё (баг 3).
- **Критичность**: high (ядро UX ввода). Модель слотов вместо append.

### E-5 ✅ tiedStop читается из MusicXML, но не сохраняется в модель → неполный round-trip
- **У нас**: импортёр парсит `<tied type="stop">` в `NoteInfo.tiedStop` (MusicXMLImporter.swift:322), но в NoteEvent кладёт только `tiedToNext = info.tiedStart` (:931, :957). Модель не имеет «tiedFromPrev». Экспортёр шлёт `<tie type="start">` при `tiedToNext` (MusicXMLExporter.swift:365), но `<tie type="stop">` — никогда.
- **Стандарт**: MusicXML требует сбалансированных start/stop у лиг. MEI/Capella импортёры тоже сводят к одному `tiedToNext` (MEIImporter:168, CapellaImporter:253).
- **Расхождение**: воспроизведение корректно (ведёт `tiedToNext` предыдущей ноты), но экспортированный MusicXML не пройдёт строгую валидацию; round-trip не тождественен.
- **Критичность**: medium-high (fidelity экспорта, не краш).

## Среднее

### E-6 ✅ Форс-анрап `first!` при инициализации автосейва
- **У нас**: `FileManager.default.urls(for: .documentDirectory, in: .userDomainMask).first!` (ScoreViewModel.swift:648).
- **Оценка**: `.documentDirectory` в песочнице iOS гарантирован → реального краша практически нет. Понижено с critical (как заявил субагент) до **low code smell**. Всё равно заменить на безопасный `guard`/`URL`.

### E-7 ❌ `max(0, delta)` при экспорте MIDI — НЕ баг (проверено)
- **У нас**: MIDIFileHandler.swift:150-155 сортирует события по абсолютному тику (`abs.sort`, при равенстве note-off раньше note-on), затем :167-171 считает дельты как разности. Комментарий :165-166 прямо: «неотрицательны по построению — список отсортирован». `max(0, delta)` (:170) — защитный no-op, не маскировка.
- **Вердикт**: ложная тревога субагента (заявлял critical «молча режет тайминг»). Дельты не могут быть отрицательными после сортировки. Снято.

### E-8 ✅ Индексы выбора не сбрасываются при insert/deleteMeasure
- **У нас**: прочитано построчно. `insertMeasureBefore` (:557-560), `insertMeasureAfter` (:562-566), `deleteMeasure` (:568-575) — ни один не сбрасывает `selectedEventIndex` (deleteMeasure клампит только `selectedMeasureIndex`). `clampSelection` (:629-643) корректен, но зовётся ТОЛЬКО из undo/redo, не из этих методов.
- **Стандарт**: любая структурная мутация обязана привести выбор в валидное состояние (как это делает clampSelection).
- **Критичность**: medium (ghost-selection, не краш — геттер `selectedEvent` возвращает nil молча).

## Кросс-режущее (архитектура)

### E-9 ✅ God-object `StaffAreaView` (1779 строк) + монолитный Canvas
- **У нас**: рендер, hit-test, spacing, жесты, спаннеры — в одном файле; отдельные почти-дубли для hit-test (:320-349) и render (:610-*).
- **Стандарт**: SwiftUI — тонкие view, тяжёлая логика в сервисах; один источник геометрии. Дублирование hit-test/render — прямой источник E-3.
- **Критичность**: high как долг (питает E-1, E-3). При пересборке — выделить LayoutEngine (единственный владелец X/Y координат), Renderer и HitTester поверх него.

### E-10 🔎 Тестируемость: логика раскладки/тайминга/MIDI не покрыта автотестами
- **У нас**: движки (EngravingEngine, PlaybackScheduler, MIDIFileHandler) вызываются из view; headless-тестов на spacing/тайминг/round-trip не обнаружено (нужен отдельный проход по каталогу тестов).
- **Стандарт**: чистая логика (маппинг высот, spacing, генерация MIDI, round-trip импорт↔экспорт) обязана иметь юнит-тесты. Правило `feedback_verify_code_before_shipping_timur`.
- **Критичность**: high как процесс — без тестов E-3/E-5/E-7 будут возвращаться.
