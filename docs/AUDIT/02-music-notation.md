## Стандарт, с которым сверяемся

- **Базовая единица — staff space (sp)**, всё масштабируется от неё (Gould «Behind Bars»; MuseScore sp=1.75мм).
- **Система = станы ВСЕХ инструментов**, перенос строки — для всей партитуры сразу, такты выровнены столбиком (MuseScore Handbook, Gould).
- **Горизонтальный spacing логарифмический** от длительности, не линейный (LilyPond springs-and-rods; `space = shortest-space + log2(dur/shortest)·increment`).
- **Ввод — replace/overwrite** по слотам, дробление паузы (MuseScore step-time).
- **Символы — SMuFL/Bravura** с зафиксированными метриками якорей (стем, флаги, добавочные линии).
- **Обмен — MusicXML/MEI/MIDI** с сохранением divisions, tuplets, ties, ключей/размеров, многостанности.

## Критичное

### M-1 ✅ Раскладка систем считается по-партийно, а не на всю партитуру (баг 7)
- **У нас**: `StaffAreaView.body` (:57) идёт `ForEach` по `score.parts`, каждая партия зовёт `EngravingEngine.computeLayout` (:68) только по `staff.measures` СВОЕГО первого стана (:66,69). → переносы систем у флейты и рояля считаются независимо; ширина такта — по одному инструменту.
- **Стандарт**: одна раскладка на всю партитуру: для каждого такта — макс. ширина среди всех инструментов, единые границы систем, единые ширины тактов, скобка/скоба слева. (ENGRAVING_REFERENCE §3.)
- **Расхождение**: станы разъезжаются по горизонтали, такты не выровнены столбиком — партитура нечитаема как единое целое.
- **Критичность**: critical. Считать layout один раз на Score (см. E-1).

### M-2 ✅→🛠 ИСПРАВЛЕНО (10.07.2026) Горизонтальный spacing линейный, а правильная лог-формула лежит мёртвой
- **Фикс**: `measureContentWidth` (EngravingEngine.swift) переведён на лог-модель
  `spacingBase + log2(actualBeats/spacingRefBeats)·spacingIncrement` (anchor = шестнадцатая 0.25).
  Константы `spacingRefBeats/Base/Increment` подобраны так, что такт из 4 четвертей ≈ прежние 160·zoom,
  но целая больше не в 8× шире восьмой. Мёртвый дубль `proportionalWidths` удалён. BUILD SUCCEEDED.
  Визуал проверяет Тимур на устройстве. Осталось: тот же принцип в X-позициях нот (E-3).

- **У нас**: `measureContentWidth` (EngravingEngine.swift:104) — `proportional = actualBeats/totalBeats · 160 · z` (прямая пропорция). Смешанная лог-формула `ratio·0.6 + logScaled·0.4` есть в `proportionalWidths` (:153-177), но **не вызывается** основным путём.
- **Стандарт**: логарифм от длительности. При линейной пропорции целая была бы в 8 раз шире восьмой — слишком широко, некрасиво, нечитаемо. (ENGRAVING_REFERENCE §4.)
- **Расхождение**: длинные ноты чрезмерно растянуты, короткие сжаты; ритмическая читаемость страдает.
- **Критичность**: high. Перейти на `база + log2(dur/shortest)·increment`, убрать мёртвый дубль.

## Высокое

### M-3 ✅ Триоли: нотоглавы по `duration.beats`, спаннеры по `actualBeats`, ширина такта по `actualBeats`
- **У нас**: см. E-3 (StaffAreaView:333/620/732 vs :843 vs EngravingEngine:104). Одна нота триоли занимает по ширине долю от `duration.beats` (0.5), но такт отмерян по `actualBeats` (0.333).
- **Стандарт**: в триоли три ноты занимают время двух; все три пути позиционирования обязаны считать по фактическому времени звучания (`actualBeats`).
- **Расхождение**: нотоглавы триоли не совпадают с их же хэйрпинами/октавными скобками; в смешанном такте триольные ноты получают лишнюю ширину.
- **Критичность**: high.

### M-4 ✅ Ввод не поддерживает выбор паузы и дробление (баг 3)
- **У нас**: `insertEvent` (:202) `.append` в конец; нельзя встать на паузу в середине такта.
- **Стандарт**: replace/overwrite, дробление паузы (ENGRAVING_REFERENCE §5).
- **Критичность**: high (см. E-4).

### M-5 ✅ MIDI-квантизация теряет структуру триолей при импорте
- **У нас**: `bestDuration()` (MIDIFileHandler.swift:559-583) прочитан: список кандидатов (whole…thirtySecond, с точками) НЕ содержит ни одной триольной/tuplet-длительности. `beats=0.666` → ближайший `.eighth dotted`(0.75, diff 0.084), триоль теряется безвозвратно.
- **Стандарт**: импорт MIDI должен распознавать tuplet-ratios (2/3, 4/6) и восстанавливать `actual-notes/normal-notes`.
- **Критичность**: medium-high (round-trip MIDI искажает ритм).

## Среднее

### M-6 ✅ tiedStop не сохраняется → неполные лиги в MusicXML-экспорте
- Дубль E-5. Модель знает только `tiedToNext`; `<tie type="stop">` не эмитится. Воспроизведение ок, экспорт неполный.
- **Критичность**: medium.

### M-7 ✅ `resolveAccidentalCollisions` определён, но не вызывается
- **У нас**: греп по всей кодовой базе — единственное вхождение это определение `EngravingEngine.swift:127`, ни одного call-site. Метод мёртв (как и лог-spacing из M-2).
- **Стандарт**: при вертикальном совпадении знаки альтерации разводятся по горизонтали (Gould). Без этого диезы/бемоли в аккорде налезают.
- **Критичность**: medium.

### M-8 ✅ Октавные сдвиги: берётся только первый на такт
- **У нас**: `PlaybackScheduler.computeOctaveShift` (:201-203) прочитан — `measure.octaveShifts.first?.kind.semitones ?? 0`; комментарий :199 сам признаёт «Грубо: первый OctaveShift». При двух разных сдвигах в такте все ноты транспонируются одинаково.
- **Стандарт**: октавная скобка (ottava) действует на диапазон нот, не на весь такт.
- **Критичность**: medium.

### M-9 ✅ Pitch.fromMIDI всегда пишет диезами, игнорируя тональность
- **У нас**: `Pitch.fromMIDI` (Pitch.swift:115-125) прочитан — фиксированная таблица `mapping` на 12 полутонов содержит только диезы (C#, D#, F#, G#, A#), ни одного бемоля; тональность на входе не передаётся.
- **Стандарт**: написание (диез/бемоль) зависит от тональности: в F-dur — Bb, не A#. Ключевые знаки не связаны с орфографией альтераций.
- **Критичность**: medium (нотный текст музыкально неверен в бемольных тональностях).
