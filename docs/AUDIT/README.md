# Аудит Composer's Notebook — карта расхождений с профессиональным стандартом

Свежими глазами, до атома, по всем дисциплинам. Задача Тимура 10.07.2026: не список
багов, а **фундамент для пересборки приложения до профессионального уровня**. Каждая находка
заземлена: «как у нас в коде (file:line, проверено грепом) → как должно быть по стандарту
области (с источником) → расхождение и его критичность».

## Методология

1. **Ставить под сомнение всё** — включая мои прежние знания, существующий код, архитектурные
   решения, И мои собственные находки/источники. Ни одна находка не берётся на веру.
2. **Синтез знаний**: мои внутренние знания (скорость, контекст) + интернет (актуальность,
   реальный код профи-движков, эталон). Где расходятся — разбираться почему.
3. **Мультидисциплинарность**: инженерия, музыка/нотация, дизайн, UX/интерфейс, и всё, что
   касается приложения (локализация, поведение на устройстве, App Store, доки, edge-кейсы).
4. **Верификация до записи**: находки субагентов и мои гипотезы проверяются грепом/чтением
   исходника ДО попадания в этот документ. Уже поймано несколько ложных тревог (см. ниже).

## Легенда статуса верификации

- ✅ **verified** — я лично открыл file:line и подтвердил.
- 🔎 **reported** — субагент/гипотеза, но я ещё не подтвердил лично. Не считать фактом.
- ❌ **false-positive** — заявлено как баг, при проверке оказалось корректным. Записано, чтобы
  не всплыло снова.
