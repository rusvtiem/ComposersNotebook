только пальцем на устройстве/симуляторе (правило `feedback_verify_code_before_shipping_timur`:
что не проверить пальцем — писать явно).

## С чем сверять (эталон)

- **Apple HIG — Gestures / Touch targets**: минимальная зона тапа 44×44pt; жесты не должны
  конфликтовать; предсказуемость.
- **Нотные touch-редакторы** (StaffPad, Notion, Symphony Pro): Select одним касанием для
  правки/транспозиции; рисование → мгновенный типсеттинг; контекстные меню. (ENGRAVING_REFERENCE §5.)
- **HIG — Accessibility**: VoiceOver labels, Dynamic Type, не только цвет для смысла.
- **HIG — Navigation**: понятная иерархия экранов, обратимость, недеструктивность.

## Находки из код-аудита (жесты)

### UX-1 ✅ Арбитраж жестов на нотном стане — хрупкий (история регресса)
- **У нас**: тап-добавление и long-press-транспозиция сидят на одном элементе; 09.07 правка
  long-press в `highPriorityGesture` проглотила тап (регресс, поймал Тимур). Сейчас сведено в
  один `ExclusiveGesture(LongPress.sequenced(before: Drag), SpatialTap)` (StaffAreaView, блок жестов).
- **Стандарт**: HIG — жесты на одном элементе должны иметь явный, неконфликтующий арбитраж.
- **Расхождение**: два независимых жеста на общем элементе — источник взаимного перехвата.
- **Критичность**: high (уже стрелял). Держать единый комбинированный жест, покрыть ручным чек-листом.

### UX-2 🔎 Зона тапа ноты не совпадает с рисунком в триолях
- Следствие M-3/E-3: hit-test по `duration.beats`, рендер тоже по `duration.beats`, но такт
  отмерян по `actualBeats` → в смешанных тактах зона и глиф смещены. Проверить пальцем.
- **Критичность**: medium-high.

### UX-3 🟡→verified VoiceOver не поддержан НИГДЕ (0 accessibility во всём коде)
- **У нас**: `grep accessibilityLabel|accessibilityElement|accessibilityValue|accessibilityAddTraits`
  по всем `.swift` — **0 совпадений**. Нотный стан рисуется через `Canvas`/`GraphicsContext`
  (StaffAreaView, MusicFontManager), а Canvas по умолчанию **невидим для VoiceOver**. Тулбар-кнопки
  тоже без явных label (полагаются на автогенерацию из текста/SF Symbol).
- **Стандарт**: HIG Accessibility — кастомную отрисовку выставлять через `.accessibilityElement(children:)`,
  `.accessibilityLabel/Value`, для сложной графики `.accessibilityChildren`/`.accessibilityRepresentation`;
  декоративное — `.accessibilityHidden(true)`. ([WWDC24 Accessibility in SwiftUI](https://developer.apple.com/videos/play/wwdc2024/10073/))
- **Критичность**: medium (не жёсткий гейт ревью, но проф-базлайн; незрячий музыкант приложением не
  воспользуется). Заход: label'ы на кнопки тулбара (дёшево) + `accessibilityRepresentation` стана
  как списка нот (дорого, отдельная задача).

### UX-4 ✅ Пустое состояние есть (placeholder-пауза), онбординга нет
- **У нас**: новый такт несёт «placeholder whole rest» (ScoreViewModel:205-227) — пустой такт показывает
  целую паузу, а не пустоту; при вводе ноты плейсхолдер чистится. Отдельного welcome/онбординг-экрана нет.
- **Критичность**: low. Пустого «белого экрана» нет; онбординг — опциональное улучшение, не дефект.
